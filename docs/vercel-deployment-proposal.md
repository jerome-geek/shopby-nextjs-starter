## 2. AWS Amplify를 선택하지 않는 이유

### 2-1. Next.js 16 버전 미지원

현재 프로젝트는 **Next.js 16.1.6**을 사용합니다. AWS Amplify는 공식적으로 **Next.js 15까지만 지원**하며, `@aws-amplify/adapter-nextjs` 패키지가 `< 16.0.0` 제한을 걸고 있어 빌드 자체가 불가능합니다.

- Amplify를 쓰려면 Next.js 15로 다운그레이드 필요
- 다운그레이드 시 React 19 의존성 호환성 재검토 필요
- 향후 Next.js 업데이트마다 Amplify 지원 여부를 별도 확인해야 하는 구조적 리스크 존재

### 2-2. SSR 콜드 스타트 문제

AWS Amplify의 SSR은 **AWS Lambda** 위에서 동작합니다. Lambda는 일정 시간 요청이 없으면 인스턴스가 종료되고, 다음 요청 시 다시 시작되는 **콜드 스타트**가 발생합니다.

**실제 서비스 트래픽 기준 분석:**

```
실측 PV 일평균: 약 16,000건
평균 req/sec:   0.18 (약 5.5초에 요청 1건)
피크 req/sec:   약 2.2
```

Lambda는 **15분 이상 요청이 없으면 콜드 스타트 발생**합니다.
평균 5.5초에 1건 수준의 트래픽에서는 낮 시간대에도 인스턴스가 자주 식어버리며, 첫 요청 사용자가 **5~7초의 응답 지연**을 경험하게 됩니다.

## 3. AWS EC2를 선택하지 않는 이유

### 3-1. 초기 세팅 복잡도

EC2에서 Next.js SSR을 운영하려면 다음을 직접 구성해야 합니다:

- Nginx (리버스 프록시) 설치 및 설정
- PM2 (프로세스 매니저) 설정
- Let's Encrypt + Certbot (SSL 인증서 수동 발급 및 자동 갱신 설정)
- 보안 그룹 (포트 22/80/443) 관리
- GitHub 웹훅 기반 배포 자동화 스크립트 직접 작성
- 예상 초기 세팅 기간: **2~5일**

### 3-2. 비용 비교 (현재 트래픽 기준)

실측 데이터 기반 DAU별 월 비용 계산 결과:

| DAU | Vercel 월 비용 | EC2 최소 비용 (ALB 포함) |
|-----|--------------|----------------------|
| 4,500 (현재 평균) | **$20** | ~$139 |
| 10,000 | **$20** | ~$261 |
| 30,000 | **$21** | ~$261 |
| 100,000 | **$26** | ~$261 |
| 500,000 | **$130** | ~$261 |

> EC2는 항상 켜져 있어야 하므로 트래픽이 적을 때 오히려 비효율적입니다.
> 인스턴스 비용 외에 ALB(로드 밸런서), 데이터 전송 비용, 보안 패치 및 운영 인건비가 추가됩니다.

## 4. Vercel을 선택하는 이유

### 4-1. Next.js와 동일 회사 제품

Vercel은 Next.js를 만든 회사입니다. 새 버전 출시와 동시에 지원이 완료되며, 버전 호환성 문제가 발생하지 않습니다.

### 4-2. Edge Runtime — 콜드 스타트 없음

Vercel은 Lambda가 아닌 **엣지(Edge) 네트워크**에서 SSR을 처리합니다. 전 세계 수십 개의 리전에 항상 켜진 상태로 배포되어 있어 콜드 스타트가 사실상 발생하지 않습니다.

### 4-3. 자동 CI/CD

- GitHub 저장소 연결 후 `main` 브랜치 푸시 → 자동 빌드 및 배포
- PR(Pull Request)마다 **독립된 Preview URL 자동 생성** — 개발팀 내부 리뷰 및 고객사 검토에 활용 가능
- 배포 실패 시 자동 롤백

### 4-4. Private 저장소 지원

Vercel Pro 플랜은 **Private GitHub 저장소를 기본 지원**합니다.
고객사 Vercel 계정에 저장소 접근 권한을 부여하는 방식으로 연동 가능합니다.

## 6. 향후 플랫폼 전환 기준

Vercel은 비용 측면에서 장기간 경쟁력이 유지됩니다. 전환을 고려해야 하는 시점은 비용이 아닌 **기술적 필요**가 발생할 때입니다.

| 상황 | 전환 대상 |
|------|---------|
| 상품/재고 인메모리 캐싱이 필요해질 때 | ECS Fargate |
| WebSocket 등 실시간 기능 추가 시 | ECS Fargate |
| 배치 작업, 크론잡 등 상주 프로세스 필요 시 | ECS Fargate |
| DAU 수십만 이상 + 전담 DevOps 인력 보유 시 | EC2 Auto Scaling |

**예상 마이그레이션 경로:**
```
Vercel  →  ECS Fargate  →  EC2 Auto Scaling
(현재)     (기능 확장 시)    (대규모 트래픽 시)
```

## 7. 배포 준비 체크리스트

Vercel 배포 전 완료해야 할 항목입니다.

### 고객사 측 준비사항
- [ ] Vercel 계정 생성 (또는 기존 계정 공유)
- [ ] Vercel Pro 플랜 결제 ($20/월) — Private 저장소 지원 필수
- [ ] GitHub 저장소 접근 권한을 Vercel 계정에 부여
- [ ] 도메인 DNS 설정 권한 확인

### 개발팀 준비사항
- [ ] `@vercel/analytics`, `@vercel/speed-insights` 코드 사용 여부 확인 및 정리
- [ ] 환경변수 목록 정리 (`NEXT_PUBLIC_*` 포함)
- [ ] `apps/web` 기준 로컬 빌드 통과 확인 (`pnpm --filter web build`)
- [ ] `vercel.json` 모노레포 설정 작성
- [ ] Vercel 콘솔에서 환경변수 등록
- [ ] 커스텀 도메인 연결 및 SSL 확인
