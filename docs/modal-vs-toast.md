# Toast vs Modal 사용 가이드

> 쇼핑몰 프로젝트에서 Toast와 Modal을 언제, 어떻게 써야 하는지 정리한 기준 문서입니다.

---

## 핵심 판단 기준

> **"사용자가 반드시 응답해야 하는가?"**

| 판단                                | 컴포넌트 |
| ----------------------------------- | -------- |
| 응답 불필요 — 결과만 알리면 됨      | ✅ Toast |
| 응답 필수 — 선택/확인/입력이 필요함 | ✅ Modal |

---

## 개념 비교

| 항목                | Toast              | Modal                |
| ------------------- | ------------------ | -------------------- |
| 목적                | 비방해적 결과 알림 | 명시적 결정 요구     |
| 사용자 액션 필요    | ❌ 불필요          | ✅ 필수              |
| 화면 점유           | 코너 일부          | 전체 오버레이        |
| 표시 시간           | 2~4초 자동 소멸    | 사용자가 닫을 때까지 |
| 흐름 차단 여부      | ❌ 흐름 유지       | ✅ 흐름 차단         |
| 되돌릴 수 없는 작업 | ❌ 사용 X          | ✅ 사용 O            |
| 추가 입력           | ❌ 불가            | ✅ 가능              |
| 복수 메시지         | 스택 가능          | 한 번에 하나         |

---

## Toast를 써야 하는 상황

사용자 흐름을 끊지 않고 결과만 알리면 충분한 경우.

### ✅ 사용 케이스

| 상황               | 메시지 예시                                               |
| ------------------ | --------------------------------------------------------- |
| 장바구니 상품 추가 | "장바구니에 담겼습니다"                                   |
| 찜 추가 / 삭제     | "찜 목록에 저장되었습니다"                                |
| 쿠폰 다운로드 완료 | "쿠폰이 저장되었습니다"                                   |
| 주소 저장 완료     | "배송지가 저장되었습니다"                                 |
| 리뷰 작성 완료     | "리뷰가 등록되었습니다"                                   |
| 클립보드 복사      | "링크가 복사되었습니다"                                   |
| 알림 설정 변경     | "알림 설정이 변경되었습니다"                              |
| 네트워크 오류 안내 | "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요" |

### 💡 Toast + Undo 패턴

되돌릴 수 있는 가벼운 작업이라면 Toast에 **실행 취소 버튼**을 붙이는 방식이 효과적입니다.
Modal을 띄우지 않아도 되고, 사용자 실수를 복구할 수 있어요.

```
"장바구니에서 삭제되었습니다"  [되돌리기]
```

적용 예시: 찜 삭제, 장바구니 단건 삭제, 비교 목록 제거

---

## Modal을 써야 하는 상황

사용자의 명시적 확인 또는 입력이 필요한 경우.

### ✅ 사용 케이스

| 상황                  | 이유                              |
| --------------------- | --------------------------------- |
| 주문 취소             | 되돌릴 수 없는 작업, 확인 필수    |
| 장바구니 전체 비우기  | 다수 항목 일괄 삭제, 비가역적     |
| 회원 탈퇴             | 고위험 비가역 작업                |
| 계정 비밀번호 변경    | 보안 민감 입력 필요               |
| 결제 전 최종 확인     | 금전 관련, 신중한 확인 필요       |
| 쿠폰 선택 (목록 제공) | 여러 선택지 중 하나를 고르는 작업 |
| 교환/반품 신청        | 사유 입력 등 추가 정보 필요       |
| 로그아웃 확인         | 세션 종료 전 의도 확인            |

### ⚠️ 고위험 작업은 이중 확인 고려

회원 탈퇴처럼 특히 위험한 작업은 Modal 안에서 텍스트 입력을 추가로 요구하는 것도 방법입니다.

```
"탈퇴하려면 '탈퇴합니다'를 입력하세요"
```

## 헷갈리는 케이스 정리

### 쿠폰 다운로드

```
상품 상세 페이지
  → [쿠폰받기] 클릭
  → 쿠폰 목록 Modal 열림       ← 선택 행위가 있으므로 Modal 적절
  → [다운로드] 클릭
  → Modal 닫힘 + Toast 표시    ← 완료 피드백은 Toast로
```

- 단일 쿠폰: Modal 닫고 Toast
- 복수 쿠폰 동시 선택: Modal 안에서 버튼 상태를 `다운로드 → 완료 ✓`로 변경 후, 모달 닫을 때 Toast 하나로 정리

### 결제 완료

Toast보다 **별도 완료 페이지**가 적합합니다. 사용자가 결과를 충분히 인지해야 하는 중요한 순간이기 때문입니다.

### 반복 액션 피드백 (연속 담기 등)

여러 상품을 빠르게 장바구니에 담는 상황에서 매번 Modal이 뜨면 최악의 UX입니다. 반복 작업 피드백은 반드시 **Toast**로 처리하세요.

### 에러 메시지

| 에러 유형                                  | 컴포넌트 |
| ------------------------------------------ | -------- |
| 즉시 조치 필요 (결제 실패, 필수 입력 누락) | Modal    |
| 단순 알림성 오류 (서버 일시 오류 등)       | Toast    |

## 요약 플로우차트

```
사용자 액션 발생
        │
        ▼
사용자가 결정/입력/확인을 해야 하는가?
        │
   YES ─┤                    NO
        ▼                     ▼
되돌릴 수 없는 작업인가?      Toast로 결과 알림
        │
   YES ─┤        NO
        ▼         ▼
      Modal     Toast + Undo 버튼 고려
```
